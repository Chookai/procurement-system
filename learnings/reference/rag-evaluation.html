General: what are we testing?

A RAG answer can fail because evidence was not extracted, search missed it, the response misused it, or a tool performed an action it should not. Our project tests these checkpoints separately.

Correctness versus groundedness: correctness asks whether the answer matches the trusted truth; groundedness asks whether its claims are supported by the supplied context. An answer can follow an obsolete PO faithfully and still be wrong for today’s question. Validate source versions and numeric facts too. Microsoft’s answer-evaluation guidance treats these dimensions separately.

Metrics: know the denominator

Use human-labelled relevant passages for this project’s retrieval evaluation. Fix the corpus snapshot and authorization scope; do not silently switch between documents and passages. Arms’ information-retrieval chapter, Evaluation section, defines the underlying precision and recall measures.

Recall@k = relevant passages retrieved in top k / all labelled relevant passages
Precision@k = relevant passages retrieved in top k / number of returned passages up to k

Our proposed convention uses the actual returned count, up to k, for precision; report that count. Empty results have precision N/A and, for answerable cases, recall 0. Cases with no relevant evidence have recall N/A and belong in a separate abstention suite.

Citations and critical facts need their own checks

Supported-citation precision (our proposed convention) = supported claim–citation pairs ÷ all evaluated claim–citation pairs. A real source ID or clickable PDF is insufficient: its passage must support that particular claim. Report missing citations separately as coverage failures; an answer with no citations must not receive a perfect support score.

Completeness asks whether required facts were covered. “6 units accepted” may be supported yet omit the requested outstanding quantity. Exact checks validate 10 − 6 = 4 from structured records; a model judge does not decide the arithmetic. nDCG@5 can later measure how well graded relevant passages are ranked, once those labels exist.

Azure terminology trap: Foundry’s Retrieval evaluator uses an LLM relevance judgment. That score is not Recall@5. Its Document Retrieval evaluator uses ground-truth relevance labels and reports search metrics; answer evaluators cover dimensions such as groundedness. Always inspect each evaluator’s inputs and output scale. Official evaluator definitions.

Release evidence: what makes a run useful?

  1. Define truth first. Freeze an identity and snapshot; label passages, expected facts, forbidden actions and abstention behavior.
  2. Develop on development cases. Tune search, prompts and judges there. Keep document families and paraphrases together when splitting.
  3. Freeze gates before holdout. Keep independent holdout cases for the release decision; do not tune against their failures and still call them unseen.
  4. Save the run contract. Dataset/corpus hashes; parser, chunker, embedding, prompt and model versions; retrieval settings; responses, citations, tool outcomes; tokens, latency and estimated cost.
  5. Report failures by layer and scenario. Critical permission failures fail the run individually. Separate deterministic checks from subjective judgments; human-review judge disagreements.

Proposed, awaiting calibration: Recall@5 ≥ 0.90 and supported-citation precision ≥ 0.95. Critical suite requires exact quantities and no observed unauthorized actions or permission leaks. These are candidate project gates, not achieved results or universal safety guarantees. The 12 development seeds do not establish production reliability.

Working terminology

RAG
Retrieval-augmented generation: retrieve evidence and supply it as context to help generate an answer.
Corpus / passage
The searchable evidence collection / one stable, identifiable piece of a source.
Gold labels
Human-reviewed expected evidence, facts and outcomes for a case.
Groundedness
Whether response claims are supported by the context supplied to the model.
Holdout
Independent evaluation cases reserved from tuning for a later decision.
Abstention
A response that states the evidence is insufficient rather than inventing an answer; inaccessible evidence must not leak through it.
Judge
A human or model applying an explicit evaluation rubric; model judgments require calibration against human labels.
