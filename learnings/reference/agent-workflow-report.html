The boundary that matters: verification applies to a fixed commit. Kilo pauses edits during that pass. A repair produces a new commit and requires appropriate rechecks.

How one ticket moves through the system

Prepare the handoff here

Agree on one ticket, its non-goals, base commit, acceptance examples, negative cases and required checks. Include applicable agent instructions, glossary and ADRs. Readiness and implementation progress remain separate.

Take the ticket to Kilo Desktop

Open the intended checkout/feature branch. Explicitly provide the instructions and scope. Kilo implements and tests, then returns a candidate commit, changed files, commands/results, artifacts and limits. It cannot weaken acceptance criteria to make the result pass.

Return the candidate here

Give me the ticket path, base/candidate SHAs and evidence locations. I verify the fixed snapshot, rerun checks and devise independent scenarios. A fresh reviewer gets the spec and code rather than the implementer's conversation. The verification pass reports first, without repairing application code.

Fix confirmed defects, then check again

Send findings back to Kilo. Confirm runtime defects with a small reproduction where feasible, and make the regression test fail before the fix and pass afterward. After three repair/review rounds, reassess the approach. You decide whether to accept or merge, especially for sensitive changes.

What verification does and does not cover

Keep human inspection for authorization, money/quantity rules, immutable evidence, migrations, CI and future agent action permissions. Fresh context or another model improves scrutiny but does not prove correctness. A static concern that cannot be reproduced remains labelled with its code path and limitations.

Code verification and RAG evaluation are separate. Retrieval labels, grounded answers, citations and unauthorized-action tests still need their own evaluation runner. The application's model runtime remains separate from Kilo's implementation model and this verification workflow.
