What happens to one uploaded policy?

01 · React + FastAPIAccept the source

Check session, CSRF, buyer role, .md/.txt extension, UTF-8 and the 64 KiB limit. Reserve a stable document and source version.

02 · Floci BlobKeep the original bytes

Store under generated IDs and preserve its SHA-256 hash. A filename is metadata, never a storage path.

03 · PostgreSQLQueue durable work

Commit the uploaded source state and unique ingestion job together. An incomplete upload is tracked for expiry and cleanup.

04 · Separate Python workerLease, parse and chunk

Claim one job atomically. Normalize line endings; split into up to 1,200 characters with 150-character overlap and retain line citations.

05 · OpenRouterEmbed the passages

Use text-embedding-3-small, 1,536 dimensions, OpenAI only and no fallback. Validate the returned model, counts and finite vectors.

06 · PostgreSQL + ReactPublish, then search

Commit all passages and the active-version pointer atomically. Combine full-text and vector rankings; return source links and line ranges.

Upload accepted ≠ source searchable. Only a complete published version enters retrieval.

Three identities keep citations honest

Document: “Invoice review policy”          stable across replacement
  Source version 1: original bytes + hash  immutable evidence edition
    Passage A: lines 1–12 + pipeline       traceable supporting text
  Source version 2: replacement bytes      separate source identity
    Passage B: new edition's line range   published only after success

Policy evidence explains procedures. Current quantities, invoice outcomes and approval authority still belong to structured procurement records and their authorization rules.

Explore the failure boundaries

Keep the last complete version

Version 1: searchable
Upload version 2 → processing → embedding error
Version 1: still searchable
Version 2: retry → complete → publish
Version 1 passages removed; version 2 becomes searchable

A slower worker from an older upload cannot overwrite the newest requested version. Historical original sources remain inspectable until document deletion.

A lease is temporary ownership

Worker A claims job → token A + 120-second lease
A crashes → lease expires
Worker B reclaims job → token B
A resumes → token A is rejected at publication

Renewal happens between bounded embedding batches. Jobs allow three attempts with backoff. An expired final attempt becomes failed. Chloe may retry the latest failed version; that begins another bounded cycle.

Hide evidence before physical cleanup

Chloe confirms deletion
  tombstone document
  clear searchable pointer and passages
  cancel ingestion work
  deny source downloads
Worker cleanup removes original blobs; storage failures retry later

A worker already calling the embedding provider must recheck the document and lease before publishing. Deletion cannot be undone by a stale worker.

Run the worker independently from the API. If it is stopped, uploads remain queued. No request handler pretends to finish ingestion.

What we verified

Credential-free contracts

The full backend suite passed 91 cases: 75 existing cases plus 16 ingestion cases against isolated PostgreSQL schemas. Blob and embedding dependencies are injected fakes in these tests.

Checks include authorization, bad sources, idempotency, retries, replacement, deletion, lease fencing, rollback and concurrent claims.

Real local integrations

Three synthetic policies completed real Floci storage, OpenRouter embedding and publication. Three labelled questions retrieved the expected source at rank one and downloaded matching original bytes.

The browser journey passed upload → search → replacement → deletion, reviewer read-only access, light/dark and 390px layout.

Live integration evidence · Browser evidence

Interpret these results narrowly: three labelled development questions are not a representative benchmark or frozen holdout. We have not evaluated generated answers, prompt-injection resistance in an agent, production identity, tenant isolation or Azure behavior.

Your review checklist

  1. Upload invoice-review.md as Chloe. Watch the processing status.
  2. Ask “Does invoice review authorize payment?” Inspect the cited version and original text.
  3. Replace the source and confirm that version 1 stays active until version 2 succeeds.
  4. Try another seeded role: reading/searching works, management controls are absent.
  5. Delete the policy and search again: that source must disappear.
