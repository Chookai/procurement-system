Lesson 02 · Inspect the application

Where does each piece belong?

Know where to look when you want to change a field, a screen or a procurement rule.

Lesson 02 · About 8 minutes · Based on our implemented code
Your win: name the owner of a change before editing code. This helps you inspect the application that will eventually host our RAG agent.

One application, two jobs

React: interact and display

Components describe the UI. State remembers things such as the selected PR; props pass values and callbacks between components. See the official React guides on components, state and props.

In our app, App owns the register and requests. RequisitionForm collects draft fields.

FastAPI: validate and act

A route pairs an HTTP method and path with a Python handler. Pydantic request models describe and validate incoming data. See FastAPI’s guides on routes and request bodies.

Our API checks identity and workflow rules, then commits accepted changes to PostgreSQL.

Names are conventions: neither framework requires files called app.py, contracts.py or main.tsx. These names tell you how our project groups responsibilities.

Follow “Save draft”

Click each step to see which part owns the work. This is a teaching walkthrough; it does not submit a request.

1. React form

frontend/src/main.tsx · RequisitionForm.save()

Aina enters 10 pump seals at MYR 200. The form collects strings from the inputs and calls its onSave prop. A prop is information or a callback passed from a parent component.

2. Browser request

frontend/src/main.tsx · App.save() → api()

App chooses POST /api/v1/requisitions. api() sends JSON, the CSRF header and an idempotency key. The browser includes its session cookie. Vite proxies /api to FastAPI during local development.

3. API + fields

backend/procurement/app.py + contracts.py

The POST route connects the request to the create handler and its dependencies. RequisitionData validates the body: for example, title is required and each quantity must be positive. Identity/CSRF dependencies also protect this route; this teaching view groups them rather than promising an order between independent validation steps.

4. Identity + rules

backend/procurement/identity.py + workflow.py

Identity establishes the active user and current role. workflow.command() allows a requester to create the draft, calculates its MYR total using Decimal, and protects repeated commands. It does not trust a role selected in the browser.

5. Database commit

backend/procurement/database.py + PostgreSQL

The transaction stores the PR, audit event and successful command response together. The SQL migration defines those tables. PostgreSQL owns the durable record; database.py manages the connection and transaction, not a second copy of the data.

6. React refresh

frontend/src/main.tsx · refresh() → setRecords()

After the save succeeds, App fetches the register again and updates its records state. React renders the saved PR and MYR 2,000 total. Browser state is a display copy; the committed database record survives a reload.

Fields, rules and tables are different

QuestionOwner in our app
What does Aina type or see?React form and rendering in main.tsx; appearance in style.css
Is quantity positive? Is the title long enough?Pydantic models in contracts.py
May this person approve this PR in this state?Identity from identity.py; permission/state checks in workflow.py
What survives an application restart?PostgreSQL tables defined by SQL migrations; transactions managed by database.py

Important boundary: the TypeScript PR type helps check our frontend code. It does not validate a network response at runtime. The backend Pydantic request model validates incoming request data; it is not the database table definition. TypeScript’s handbook explains that types are erased.

Same responsibilities on Azure

Our proposed Azure setup could serve the built React assets through Static Web Apps and run FastAPI in Container Apps, with managed PostgreSQL for storage. Those hosting choices do not turn React into the permission authority or replace contracts.py with a database schema. This is a future project mapping; no Azure deployment is claimed.
